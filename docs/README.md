## 维护约定

1. 修改代码时，同步更新受影响的文档；新专题加入本索引，原有文档直接修订，避免每轮新建一份重复总结。
2. 选型已落地或里程碑变化时，同步修改主规划的决策表、状态表和启动清单，不能只写进度日志。
3. “已实现”只描述代码；“已配置”只描述脚本或 CI；“验证通过”必须说明日期、环境、命令/用例和范围；未执行的检查保持“未验证”。
4. 记录未完成项和下一步验收条件，不用完成率或推测性性能数字代替证据。真实数据与合成样本必须区分。
5. 提交前检查文档路径、链接、命令与当前代码一致。纯文档修订记录为文档核对，不冒充本轮重新执行了应用测试。
6. 每个功能同步维护 `doc/feature-list.md`；产品里程碑完成、功能验收、PR 合并和下一阶段授权分别核实。合并后的实际状态以远程 PR 为准，下次获授权时对账。

仓库级协作约定见 [AGENTS.md](../AGENTS.md)。
