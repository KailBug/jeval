## 接入前需要确认

先取得获准使用的脱敏样本，再固定解析范围。拟从本地 JSONL 记录入手；具体目录、事件名称、字段和版本变化行为都以实际样本与相应来源代码核对，不在此提前作兼容承诺。

样本需覆盖：普通会话、长工具输出、工具失败、父子/分支关系、缺少完成信息，以及追加中的不完整记录。每份样本登记来源版本、脱敏处理和可公开范围；不得直接将用户完整私有日志提交到仓库。

需要形成映射说明：

- 来源身份、会话与运行如何对应；什么条件可判定为同一条记录。
- 原始顺序、工具调用与结果、分支/父子关系如何保留。
- 哪些状态、时间和指标有来源依据；缺失时继续使用 unknown/null。
- 标准化事件如何定位到原始文件/事件，以及如何说明快照版本。
- 未知事件、坏行、半行、超大记录如何报告或恢复。

## 下一步实施顺序

1. 建立脱敏样本及映射说明，注明支持与不支持的记录范围。
2. 先实现显式选定输入的只读解析和查询，用真实事件替换演示链路进行验证。
3. 加入目录入口、来源范围校验、单文件失败反馈和可取消扫描。
4. 在来源身份确定后实现 SQLite、检查点、去重与增量同步。

验收应证明：原始记录不被修改；事件可追溯；未知字段/状态不会被误判；重复扫描无重复任务；追加、半行、截断、轮转和重启均有恢复测试。导出后再次导入属于后续记录管理链路，当前尚未实现。
