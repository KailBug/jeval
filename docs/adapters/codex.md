# Codex 适配器

更新日期：2026-10-05。状态：**classic / paginated rollout JSONL 导入、已确认预览快照持久化和手动更新已实现；2026-10-04 一份 Codex 0.160.0 真实文件已在本地通过复测，完整版本兼容矩阵未验收**。本轮 B 接入本地任务库；没有重新读取私人记录或核对上游格式。

点击“导入 Codex 记录”选择一个 `.jsonl` 文件，或点击“发现本地任务”选择一个目录。单文件直接导入；目录扫描完成后弹出候选选择窗口，默认不勾选，确认导入后才更新任务库并切换到 Codex 来源。不会自动扫描用户目录，不需要 API key，也不会发送日志到远程服务。

## 显式目录发现

用户通过系统目录选择器指定本次范围，后台递归检查 `.jsonl`（扩展名忽略大小写），不要求 rollout 文件名；非 rollout JSONL 按失败项展示。所选根目录先解析链接，子目录中的符号链接、Windows junction 和特殊文件跳过计数。目录或文件读取失败只记录该项，继续其他项；源端并发替换、权限改变或写入不具备文件系统事务保证。

按保存目录 ID 重新发现时会核对已保存的规范化根路径；如果该路径后来被链接/junction 替换并指向其他目录，会拒绝扫描、要求重新选择，不登记或扫描新的目标。

扫描只生成候选摘要，不写任务库，也不替换已有记录。结束、达到扫描上限或取消后弹出候选窗口，支持按标题/项目/路径搜索、浏览概要与首条消息预览、逐条勾选、全选及确认导入。全选覆盖所有可选候选，不仅是搜索结果；成功导入的候选禁用，已有记录显示“将更新已有记录”。关闭窗口或 Esc 不导入，之后可以“浏览扫描结果”重新打开。候选概要通过分页读取，首条消息最多预览 500 个字符，不保留所有候选事件。

确认导入只发送扫描 ID 与候选 ID，引擎不接受渲染层指定路径。导入前按所选集合检查总配额，超额时整批拒绝、没有部分写入；通过后后台逐文件重读，并对比扫描时的路径身份与字节摘要，变化或读取失败则提示重新扫描且保留旧快照。候选数量上限不受 20 条任务库配额影响，可以先浏览再挑选。任务库配额仍为 20 个文件 / 50000 个总事件，全选也必须满足这个限制。

扫描展示根目录、检查条目、有效候选、失败与跳过数量；导入阶段另显示新增/更新与失败。阶段切换时重置导入计数和错误列表，候选保留状态。每阶段失败计数完整，详情最多展示前 30 项。单文件非致命解析提示计数在候选中可见，详细提示在导入后的“导入信息”中查看。

一次仅运行一个发现或所选导入任务，读取与两轮解析均检查取消，发布快照前再次检查。发现取消只保留已发现摘要；导入取消保留已完成的所选记录，确认取消后不再发布快照。完成后再次取消为幂等操作。系统阻塞读调用无法强制中断，慢盘/网络盘的取消耗时不承诺固定上限。单文件导入/更新与后台任务互斥；关闭或重启引擎取消任务、清除候选，已提交快照保留。导入完成后刷新任务库；扫描和仅浏览候选不会改变列表。

目录每批读取 64 项，最多检查 10000 项、200 个 JSONL、32 层子目录。达到遍历上限时停止扫描、显示原因，仍可选择已发现候选。遍历顺序由文件系统决定，不承诺按时间排序；建议选择较小目录。再次扫描完整重读生成新的候选，只有再次确认导入才按路径替换；源文件删除不会自动删除任务库记录。这不是检查点增量同步。有效的显式根目录最多保存 20 项，用户可按配置 ID 再次扫描或移除；移除不删已确认记录，启动不自动扫描。

## 格式与验证范围

适配范围为 rollout：逐行 `{timestamp, type, payload}`，含唯一的 `session_meta`，以及 `response_item`、`event_msg`。接受缺省、`classic`、`paginated` 的 history_mode；未知模式仍明确拒绝。此前仅允许 classic，导致 Codex 0.160.0 的 paginated 文件在读取 metadata 时被拒绝，本轮已修复。

字段核对依据是 OpenAI Codex 的 [ResponseItem 定义](https://github.com/openai/codex/blob/main/codex-rs/protocol/src/models.rs)、[rollout 持久化策略](https://github.com/openai/codex/blob/main/codex-rs/rollout/src/policy.rs) 和 [回合状态协议](https://github.com/openai/codex/blob/main/codex-rs/docs/protocol_v1.md)，核对日期为 2026-10-04。上游格式持续变化，本实现仅支持下表子集，不承诺覆盖某个发布版本的所有记录。

仓库中的 [classic.jsonl](../../fixtures/adapters/codex/classic.jsonl) 和 [paginated.jsonl](../../fixtures/adapters/codex/paginated.jsonl) 完全由人工构造，synthetic 版本字段不是 Codex 发布版本。本轮按用户指定路径只读检查了一份真实 0.160.0 文件，但没有把私人内容、绝对路径、会话 ID 或截图加入仓库；尚无获准公开的真实脱敏样本集。

| 输入                                                            | 转换与边界                                                                                                                                    |
| --------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `session_meta`                                                  | 保留会话 ID、cwd、cli_version、history_mode、forked_from_id、parent_thread_id；父线程与分支来源分别展示，不混为一谈                           |
| `response_item.message`                                         | 展示 user/assistant/system/developer 文本；其他内容块显示占位，不加载图片或附件                                                               |
| `function_call` / `custom_tool_call`                            | 工具名与参数/输入；保留 call_id 关联，重复 call_id 拒绝导入                                                                                   |
| 对应的 `*_output`                                               | 展示结果原文或 JSON，按 call_id 指向父调用；找不到调用时给出提示                                                                              |
| `event_msg.task_started/task_complete/turn_aborted`             | 展示为回合状态事件；不据此判定整个会话成功、失败或仍在运行                                                                                    |
| `event_msg.error`                                               | 展示来源错误，不将单个工具/回合错误推广为会话失败                                                                                             |
| `event_msg.user_message/agent_message`                          | 忽略镜像消息，避免与 response_item 重复；仅含镜像的格式不在完整兼容范围内                                                                     |
| `event_msg.item_completed`                                      | 支持 UserMessage/AgentMessage，识别 text/Text 内容；优先保留 canonical response_item，按 ID 或同回合的角色/文本摘要去重，只有投影时保留该消息 |
| `turn_context`、`event_msg.token_count`、`token_usage_record`   | 暂不展示或计算；耗时、token 为 null，会话状态为 unknown                                                                                       |
| `world_state`、`thread_settings_applied`、reasoning / Reasoning | 已知的环境、设置与内部推理记录，不作为可见时间线事件，不重复产生未知类型提示                                                                  |
| 未知类型、无效行与尾部半行                                      | 跳过并登记物理行号，不停止处理后续合法行                                                                                                      |

## 身份、证据与重复导入

- 文件身份来自解析符号链接后的绝对路径哈希；Windows 按不区分大小写的路径去重。相同路径重导入时完整替换该记录，不追加重复事件；不同路径的副本保留为不同记录。
- 会话 ID 和分支来源单独保留，不将每个回合强行拆成独立运行，也不跨文件自动合并会话。
- paginated 消息去重先检查整个文件中的 canonical 消息，支持投影先于原消息写入；文本匹配限制在同一回合，不把不同回合的同文提示合并。未知 item_completed 类型仍给出提示，不宣称覆盖所有投影工具类型。
- 每个事件的 ID 包含文件身份与一基物理行号；`parentId` 只按来源 call_id 关联，支持结果先于调用的记录。
- 新增适配器版本及快照 ID，事件证据绑定同一快照；永久引用必须包含快照 ID，不能只用事件 ID 或物理行号。算法和字段以 [记录契约](../../contracts/record/README.md) 为准。
- 导入信息保存实际读取字节的 SHA-256、来源路径、版本及解析提示。摘要用于核对本次读取，不等于源文件已被持久化备份；读取正在写入的文件不提供源端事务一致性保证。
- 再次导入发生致命错误时保留上一份可用记录。截断、替换后的合法文件可通过重导入更新，但这不是检查点式增量同步。

## 上限与当前限制

单文件最多 16 MiB、50000 行以内、5000 个标准化事件；路径最多 2048 UTF-8 字节。单事件正文保留前 8 KiB 预览并明确标注截断，原文仍在用户文件中。提示总数完整计数，详情最多展示前 30 项。任务库最多登记 20 个文件，总当前事件数最多 50000（含演示），重启不重置配额；历史快照不计入当前配额，当前没有磁盘清理策略。超限文件拒绝导入，不伪装成完整结果。

桌面已确认记录保存到本地 SQLite，应用/引擎退出后可恢复，源文件离线仍可查询保存的预览与证据位置。“刷新记录”只查询保存列表；“更新已登记记录”以运行 ID 完整重读已登记路径，读取/写入失败保留旧版本。证据文件路径表示导入时位置，不保证当前仍存在；没有原始 JSONL 副本。单文件解析/更新仍无取消入口，目录扫描/所选导入可取消。默认目录建议、自动扫描、文件监听、检查点和完整正文存储未实现。

## 本轮检查与后续验收

Go 测试覆盖映射、镜像去重、工具关联、来源字节不变、中文/空格路径、坏行/半行、无效时间、UTF-8、超大文件、事件上限和未知类型。跨进程测试覆盖重复导入、原子替换失败和大段转义文本的字节分页；B 新增真实引擎重启、离线读取、目录配置和失败更新检查。桌面测试通过系统选择器返回值模拟选择，实际执行 IPC → Go 读取与查询，具体本轮结果见 M0 进度。此前“重启清空”的内存行为仅保留在无参数独立引擎测试模式。

本轮增加 paginated 回归：镜像先后顺序、跨回合同文消息保留、缺少 canonical 的消息回退、父线程来源和工具关联。用户指定的 0.160.0 文件已在开发构建及最终目录包中复测：107 个事件、55 条消息、3 页查询，来源文件字节摘要不变；12 项提示均为 8 KiB 正文预览截断，不是解析失败。Electron 实际导入和 Windows 原生窗口控制覆盖层可见性检查通过，私人内容未进入测试产物。

上述真实检查只覆盖一份消息/回合记录，不能推广为所有 0.160.0 功能均兼容。本轮使用合成目录和独立测试库，未重新读取私人会话；仍需真实目录、公开脱敏样本和发布版本矩阵、复杂工具投影、长日志性能、系统选择器人工验收，以及检查点增量同步。整体状态见 [M0 进度](../development/m0-progress.md)，字段以 [记录草案](../../contracts/record/README.md) 为准。
