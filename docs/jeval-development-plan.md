# jeval 项目开发规划

规划日期：2026 年 10 月 3 日\
最近更新：2026 年 10 月 8 日\
文档状态：M0 开发中，尚未完成验收（见 [M0 进度](development/m0-progress.md)）\
适用对象：项目作者与后续开源贡献者

jeval 是面向 Agent 和 harness 开发者的桌面工作台。最终目标是导入并分析不同 harness 的 trajectory，对上下文管理、工具、规划执行、重试恢复、协作及成本延迟等部分提供有证据的分析和可复现对比验证，兼容 Langfuse 与 Harbor 的数据格式及评测方式，让用户在 eval 中选择启用 Jev 加速和辅助分析。支持范围通过来源、版本和能力矩阵逐项验收，不笼统宣称覆盖所有市场产品。

开发采用 Electron 与 TypeScript 构建桌面应用，使用 Go 实现独立采集引擎。第一版先交付“发现任务、查看记录、按需分析、导出”的完整流程，再扩展实验执行与回归评测。Codex 本地预览与 v0.1 Alpha 是中间交付，不是最终终点。具体执行队列见 [feature-list](../doc/feature-list.md)，阶段授权与合并规则见 [阶段开发流程](development/stage-workflow.md)。

## 当前实现状态

截至 2026-10-08，已打通 Electron + React → preload → 主进程 → Go 引擎的浏览链路。A 的 SQLite 基础已在 B 接入桌面任务库，检查结果见 [M0 进度](development/m0-progress.md)。C 已增加单个已保存 Codex 快照的原生 JSON 导出/再导入与 Markdown，保留证据与未知值，来源离线仍可交换；只读交换记录不授权读取旧路径，具体实现与检查见 [M3 进度](development/m3-progress.md)。除三条合成演示外，现已支持 classic/paginated Codex rollout JSONL 显式导入、来源筛选、消息投影去重、时间线与物理行号定位；历史的一份 0.160.0 真实验证不等于完整版本矩阵。窗口标题栏支持记录/来源的前进后退，不调用 Jev。

“发现本地任务”现分为发现和确认导入：扫描后弹出二级窗口，可搜索和浏览候选、逐条勾选或全选，确认后才更新任务库；扫描本身不导入。已增加记录内关键词搜索与事件类型筛选，跨当前快照所有事件查询后分页，保留证据引用。有效的显式选择目录保存为配置，启动不扫描；D01 已实现可取消的检查点更新，安全追加只解析后缀，仍完整读取并校验来源；默认目录建议和文件监听未实现。依据见 [M2 进度](development/m2-progress.md)。

首个本地来源已由用户确定为 Codex。Windows 是当前验证平台，A02 已完成本机 NSIS 安装/启动/卸载与原生选择器，干净环境仍未验收。A01 已补有限真实来源矩阵；M0 仍缺更广版本/来源映射和安装链路验证；存储基础和身份决策已进入可运行验证。M1/M2 已有跨阶段实现，但均未整体验收；完整页面验收随各功能推进，不再全部压在 M0。

## 本次规划调整与近期重点

当前最短交付路径是把已能浏览的 Codex 记录变成可保留、可复查、可交换的本地工作资料。Go 学习与工程展示继续围绕真实需求展开，近期聚焦事务、恢复、来源身份和有界查询。

- 保留 M0–M5 编号追踪中间版本，新增 M6–M8 追踪多来源、分部件分析与最终产品；执行按有依赖的单功能清单串行推进，不按编号重做已有功能。
- 先补真实来源证据和持久化，再做统一记录导出/再导入、增量更新与基础对比。Jev 在本地预览门槛通过后进入实现。
- v0.1 Alpha 聚焦 Codex、Windows x64 和两个可选 Jev 检测器；ATIF、其他 harness、Langfuse 和 Harbor 评测兼容在 Alpha 后继续交付，属于最终目标必交范围。文件监听、第二主题与自动对齐不阻塞首版。
- 保留“发现 → 默认不选 → 用户确认导入”的交互。保存目录不等于授权自动导入新文件；同步只更新已登记记录，新发现记录仍需选择。
- 暂停使用原先从零估算的 26–43 个有效工作日作为剩余工期。每个切片完成后依据实际缺口估算下一片；真实样本、干净测试环境与许可证决定分别记录，不以加功能代替验收。
- 用户已授权使用本地测试环境、公开轨迹及至少三个月前的本地旧轨迹；具体日期、只读及公开范围按阶段流程核对。每阶段自动开发至验收、CI、PR 合并及 main 快进同步，随后必须等待用户“继续”。不创建 worktree，不设置人为用量或失败次数上限；D03 已合并，本轮明确授权串行交付 E01 和 E02；用户确认没有独立测试环境，先完成本机验证并保留干净环境待办；未部署调度器。

目前持久化任务库最多保留 1000 个导入文件、50000 个当前事件（含演示），单文件最多 10000 个事件、事件 JSON 保留 8 KiB 预览加截断提示，D02 另存完整标准化文本供按需查看；重启不重置配额。任务每页最多请求 10 条，事件每页最多请求 50 条，都按编码预算调整，新页替换当前页。B/C 交换仍为标准化预览，D02 正文可本地分页查看；原始附件、全文搜索/交换仍后置；D03 规模依据仅覆盖固定合成样本，见规模验收。

本文后续的“首版范围”“实施要求”和“验收”均为目标要求，不代表已实现。当前代码职责见 [M0 架构](architecture/m0-architecture.md)，操作入口见 [开发运行指南](development/getting-started.md)，全部文档见 [文档索引](README.md)。

## 用户与核心使用场景

第一批用户是个人 Agent 开发者、harness 作者，以及需要检查本地 Agent 执行记录的工程师。

| 场景 | 用户的问题 | 产品应交付的结果 |
| --- | --- | --- |
| 查找任务 | 上次运行的记录在哪里 | 按来源、项目和时间组织的任务列表 |
| 复盘失败 | 为什么反复尝试仍然失败 | 可展开的执行时间线和可定位的原始证据 |
| 检查完成情况 | 最终回复与实际执行是否一致 | 验证结果、产物信息与完成声明的并列查看 |
| 比较改动 | 两次运行具体哪里不同 | 元数据、指标、执行记录的并排对比 |
| 分享问题 | 怎样让别人复现或理解问题 | 带版本和来源信息的记录包、诊断与人工标注 |
| 后续评测 | 某项 harness 策略是否有效 | 在控制实验条件下运行任务并比较结果 |

“导入”指将已有数据登记或复制到 jeval；“导出”用于备份、分享或外部使用。用户查看和分析记录时，不需要先手动导出再重新导入。

## 第一版范围

首个公开版本建议命名为 v0.1 Alpha，以明确版本和能力范围内的 Codex 为必交来源。先形成无模型依赖的本地预览，再加入 Jev 和公开发布材料；ATIF 文件或结果目录导入后置。下表为 Alpha 目标，不表示当前已有能力。

| 能力 | 首版交付范围 | 验收要点 |
| --- | --- | --- |
| 开箱演示 | 内置明确标识的合成或获准脱敏演示记录及预存分析 | 无密钥也可体验，不将演示结果伪装成当前模型调用；当前仅有合成记录，无预存分析 |
| 本地发现 | 常用记录目录与用户添加目录 | 扫描可取消；能看到来源、进度、失败项 |
| 任务库 | 来源、项目、时间、状态筛选及文本搜索 | 未知状态和缺失数据有明确展示 |
| 统一查看 | 消息、工具调用、结果、错误、验证与分支关系 | 每个标准化事件可追溯到原始来源 |
| 增量同步 | 更新已登记记录 | 重复扫描不重复建任务；支持重启后继续 |
| Jev 分析 | 用户主动触发，两类检测器 | 可关闭、取消；结果附证据、版本和分析范围 |
| 人工标注 | 接受、否定、待确认和备注 | 人工意见与模型结果分别保存 |
| 基础对比 | 两份记录并排查看和指标对比 | 支持手动选定对比记录；不按相同步骤编号强行对齐 |
| 导出 | 统一记录 JSON 和便于阅读的 Markdown 报告 | 导出说明缺失字段、快照范围与模型诊断性质 |
| 安装运行 | 一个验证过的首发平台 | 安装包携带 Go 引擎，用户无需安装开发工具 |

首版暂不承担跨平台全部适配、自动修改代码、自动停止 Agent、云端团队协作、完整实验调度、自动优化 harness、公开排行榜和多模型分析后端。它们应以独立里程碑进入后续版本。

## 首次使用与日常流程

目标流程：首次打开时，用户可以先浏览演示，也可以点击“发现本地任务”。扫描范围显示为具体来源和目录，用户可增删已保存目录。扫描先展示候选摘要，用户确认后持久化导入，打开任务时分页加载详情。当前扫描仍完整解析文件以生成摘要，尚未实现轻量磁盘索引。

任务库按项目和来源组织，支持最近更新、错误状态和手动收藏。来源记录无法确定是否结束时显示“状态未知”；正在追加的记录显示“更新中”，不据此推断 Agent 已成功或失败。

打开任务后，用户可以搜索消息，展开工具参数与结果，跳转错误或验证步骤。点击“使用 Jev 分析”后，选择检测器和分析范围，查看将发送的内容，再发起本次分析。分析在后台执行，基础浏览保持可用。

用户可以在诊断上添加意见，选择另一份记录比较，或者导出当前快照和报告。删除 jeval 内的索引、快照或分析结果，与删除原始 harness 文件是不同操作；首版只提供前者。

## 界面与视觉验收

视觉设计在开发早期完成，并贯穿每个里程碑。优先验证高信息密度下的可读性、层级和操作反馈。

| 页面 | 主要内容 | 关键交互 |
| --- | --- | --- |
| 欢迎与数据来源 | 演示、本地来源、导入入口 | 一键发现、添加目录、查看适配状态 |
| 任务库 | 项目分组、任务列表、筛选与搜索 | 多选、排序、打开任务、导出 |
| 执行详情 | 左侧导航、中间时间线、右侧检查面板 | 展开工具、跳转证据、查看原始记录 |
| 分析结果 | 检测器结果、证据位置、人工反馈 | 接受或否定诊断、重新分析 |
| 记录对比 | 两份记录、关键指标与差异 | 手动定位对应片段、独立滚动 |
| 设置 | 来源目录、Jev、存储与应用信息 | 连接测试、配置开关、清理本地缓存 |

先设计任务库、执行详情和对比页的关键状态，使用真实长度的日志和工具输出验证布局，再扩展其他页面。

轨迹交互参考用户指定的 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)，重点为回合/步骤分组、工具与子工具层级、时间概览、输入输出检查及长列表浏览；实验和评分组织参考 Langfuse。它们是后续设计依据，不是本轮 UI 改动或完成声明；具体切片与验收见 [界面说明](design/m0-ui.md)。

视觉验收要求：

- 统一字体、字号、间距、颜色、圆角和状态组件；状态同时提供文字，不能只靠颜色区分。
- 完整覆盖空数据、加载中、部分失败、无密钥、不支持格式、记录缺失和分析取消状态。
- 长文本按需展开，工具输出使用虚拟列表或分页；避免一次渲染全部记录。
- 支持键盘导航、可见焦点、可调整面板宽度及减少动态效果的系统偏好。
- 检查至少两种窗口尺寸与首发系统的常用缩放比例，验证中文、英文和长文件路径。
- 首版优先打磨一套主主题，并预留主题变量；第二套主题在不影响核心交付时加入。

## 技术结构与职责

| 模块 | 建议技术 | 职责 |
| --- | --- | --- |
| 桌面渲染层 | TypeScript 与 React | 任务库、时间线、对比和状态交互 |
| Electron 主进程与 preload | TypeScript | 窗口、文件选择、受控 IPC、凭据访问和 Go 进程生命周期 |
| 采集核心 | Go | 扫描、读取、解析、转换、增量同步、查询和导出 |
| 来源适配层 | Go | 屏蔽不同来源的数据格式与获取方式 |
| 分析模块 | 建议放在 Go 独立包 | 规则检测、Jev 调用、任务队列与结果归档；不与采集逻辑耦合 |
| 存储 | 建议 SQLite 与独立快照文件 | 索引、标准化事件、分析、标注、同步进度及原始数据快照 |

Go 引擎编译为独立可执行文件，随应用分发，由 Electron 主进程启动。首版与应用同生命周期；独立常驻模式放到后续。Electron 主进程运行于 Node.js，可通过其子进程能力启动可执行文件，渲染层通过 preload 暴露的有限接口调用业务功能。[Electron 进程模型](https://www.electronjs.org/docs/latest/tutorial/process-model)、[Node 子进程文档](https://nodejs.org/api/child_process.html)

建议在同一仓库中维护桌面端、Go 核心、数据与通信协议、样本、文档和 CI。统一记录 schema 与通信协议单独版本化，并使用同一份样例验证 TypeScript 和 Go 的解释一致。

## 数据模型与来源适配

首版使用小而明确的内部模型，保留源格式的扩展字段。统一展示不等于所有来源拥有相同的信息。

| 实体 | 主要信息 |
| --- | --- |
| Source | 来源类型、位置、原始版本、适配器版本、同步状态 |
| Project | 项目名称、路径或来源项目标识 |
| Session | 会话标识、标题、项目、父子或分支关系 |
| Run | 一次执行或快照、来源标识、模型与 harness 元数据、可用指标 |
| Event | 消息、调用、结果、错误、验证、时间戳、顺序与父子引用 |
| ArtifactRef | 产物位置、类型、快照状态及可用性 |
| Finding | 检测器、结论、概率或分数、证据事件、分析版本与覆盖范围 |
| Annotation | 用户意见、备注、时间与关联对象 |

不同来源未必区分 Session 和 Run。适配器应记录映射依据，不将任意一次对话自动解释成独立实验。并行调用、子 Agent 与会话分支保留关系，时间未知时不能伪造时间戳。

每次归一化记录来源 ID、文件位置或远程定位信息、适配器版本和快照摘要。重复导入按来源身份和内容版本去重；跨平台来源之间只标记可能重复，避免自动合并不同执行。

本轮 C 已实现单个已保存 Codex 预览快照的原生 JSON 导出/再导入，必要交换字段与版本规则已冻结为 [交换 v1](../contracts/exchange/README.md)；底层字段见 [记录契约](../contracts/record/README.md)，完整来源模型与其他管理对象仍为开发草案。ATIF 是最终目标的外部交换格式；实现前核对 [Harbor ATIF 文档](https://docs.harborframework.com/agents/atif)，锁定版本并用上游验证器检查导入/导出，记录无法映射的字段和扩展字段处理，不将其等同于 jeval 原生导入。

后续 Langfuse 连接器通过用户配置的实例与凭据读取数据，并保留 observation 的父子关系。实现时按实例版本选择可用 API，采用时间范围和分页，不能把“本地扫描”包装成自动发现远程项目。[Langfuse 公共 API](https://langfuse.com/docs/api-and-data-platform/features/public-api)

Langfuse 文件导入、实例读取、实验与评分交换分别验收：保留 trace/observation/session 与 dataset/run/item/score 的关系，对照上游测试实例验证数量、引用、未知值和回写语义。导入成功不代表双向兼容。[轨迹模型](https://langfuse.com/docs/observability/data-model)、[实验模型](https://langfuse.com/docs/evaluation/experiments/data-model)

Harbor 兼容分为 ATIF 轨迹、任务/作业/试验结果及受控任务运行；保留环境、配置、原生 verifier/reward、错误和轨迹关联。每种导入、导出或运行衔接分别列明版本和支持子集，使用上游工具/测试任务复核，不能把读取一个 JSON 文件视为整个评测方式兼容。

## Go 采集引擎实施要求

来源适配器应表达自己支持发现、列出任务、读取、增量更新还是远程获取。首版可先实现具体适配器，再抽取有实际复用价值的公共接口。当前 Codex 已实现用户选定文件或目录中的 JSONL 只读解析、可取消的后台目录扫描、已确认预览/完整标准化文本持久化与手动检查点更新；格式子集、扫描上限、合成验证与待验收内容见 [适配器说明](adapters/codex.md)。检查点语义和回退范围见 M2 进度；文件监听仍未实现。

采集流程包括目录发现、任务索引、事件解析、格式转换和事务写入。首次扫描与增量扫描分别记录进度。文件监听作为更新提示，结合检查点和补扫恢复，不能假定每次文件变化都会收到通知。

需要覆盖以下行为：

- 半行 JSON、追加写入、截断、轮转和文件替换均不会导致永久停止同步。
- 一个坏文件或无权限目录产生独立错误，其他来源继续处理。
- 并发数、队列和单条事件大小有上限；扫描、读取和导出支持取消。
- 读取数据库或其他结构化存储时采用该来源适合的一致性方式，不修改原始记录。
- 所有数据库写入由 Go 管理；大段内容按需读取，界面使用分页查询。
- 检查点与数据写入保持一致，重复处理允许去重，重启后不丢失已确认的数据。
- 本地存储迁移、备份和可恢复失败有明确流程。

主动采集属于后续版本：在同一核心上增加可选 HTTP 接收端，允许其他语言通过 SDK 或 hook 上报事件；必要时增加 OpenTelemetry 接收适配。它不能恢复历史上未被记录的工具调用或模型信息。

## 桌面通信与进程管理

已采用标准输入输出上的逐行 JSON 协议，请求、响应和能力声明以 [协议 v1](../contracts/protocol/README.md) 为准。当前扫描进度使用状态轮询；新增持久化、更新和导出方法时同步维护契约与跨进程用例。通知推送只在实际需要时引入。

握手返回引擎版本、协议版本和可用能力。普通调试日志写入 stderr。大型轨迹按页查询或通过受控文件引用传输，避免将整段日志放进一条消息。更新通知可以合并，避免界面处理不过来。

Electron 管理启动、就绪、退出和异常状态。Go 退出后，界面应显示恢复入口；重连后重新查询未完成任务，不自动重复非幂等操作。关闭应用时先请求取消与落盘，再在限定时间后结束进程。

## Jev 分析设计

Jev 开关从第一版进入产品设计。默认基础功能不依赖 API key；用户主动启用后才执行远程语义分析。关闭开关停止排队任务，并尽可能取消进行中的请求；已经发送的内容无法通过取消撤回。历史结果继续可读。

首版保留两类语义检测器：

| 检测器 | 输入与问题 | 结果边界 |
| --- | --- | --- |
| 无效重试 | 相邻尝试、错误、状态变化与新增证据；是否反复执行实质相同的无效策略 | 输出疑似片段与证据，区分合理重试和探索 |
| 完成证据一致性 | 最终声明、最近相关验证和产物信息；声明是否受到记录支持 | 区分受到支持、证据矛盾、证据不足 |

退出码、完全相同的调用、耗时和数量由代码计算。Jev 处理剩余的语义问题。类型化判断与概率是 Jev 的接口能力，但模型概率不是事实证明。[Jev 官方文档](https://docs.typesafe.ai/introduction)

使用相关片段而非无条件发送整段轨迹；保留事件 ID、截取规则和覆盖范围。输入过长时显式分段或报告无法分析，不静默截断关键证据。首版优先按单项声明或片段判断，再由代码汇总；泛化的长篇解释不是必需能力。

每次分析记录输入摘要、来源快照、模型返回版本、检测器与问题版本、阈值版本、耗时、用量和实际错误。缓存键包含这些影响结果的因素；复用结果必须标记缓存状态。无法取得的费用标为未知，估算费用标记计算口径。

用户标注不覆盖模型原始结果。检测器变更后旧结果标记版本差异，重新分析由用户发起。Jev 错误、超时和证据不足应独立呈现，不能被解释为通过检查。

## 诊断质量与评测方法

首版先构建一组有人工标注的真实脱敏轨迹片段，并补充明确标为合成的边界用例。建议从每类检测器数十个样本起步，用于暴露问题，不据此宣称普遍有效。

样本需包含正常探索、合理重试、无效重试、验证通过、验证失败和证据缺失。按任务或项目划分开发集与留出测试集，避免同一次运行的相邻片段分散到两边。问题和阈值在开发集上调整，测试集用于最终报告。

对比纯规则、规则加 Jev，以及资源允许时的普通 LLM 判断。报告每类检测的误报、漏报、精确率、召回率、无法判断比例和覆盖率；同时记录分析费用、端到端延迟和样本量。评估器自身超时与程序错误单独统计。

用户界面用“疑似问题”呈现尚未人工确认的诊断。离线发现重复尝试不等于已经证明能够节省 token 或提高成功率；这类收益需要后续实际干预实验验证。

最终的“成熟分析”须按 harness 部件分别验收：上下文/压缩、工具使用、规划执行、重试恢复、多 Agent 协作及成本延迟。每项列出所需观测、确定性指标、规则基线、Jev 可选判断、证据引用和无法分析条件；未知数据不补造。进入留出评测前冻结问题、阈值、样本划分与通过标准，公开样本量、误报/漏报、覆盖率和不确定性，不以一份分析长文作为成熟标准。

比较 harness 改动时记录任务/数据集、模型、配置、环境和评测器版本，对同任务配对并保留重复次数、失败与缺失分布。历史轨迹的相关性用于提出假设；提升成功率或降低成本的结论须有受控复跑或干预证据。eval 中关闭 Jev 仍能执行原生评分和确定性比较；启用后的诊断与原生结果分开，验证质量、时间和费用再声称加速收益。

## 数据处理与桌面边界

扫描范围限定于已适配来源的常用目录和用户添加目录，发现与浏览保持本地处理。Jev 分析明确展示输入范围；远程数据连接和分析各有自己的开关。

凭据通过系统凭据存储或经过验证的桌面加密存储方案管理，不写入普通日志、导出包或默认配置文件。未验证的平台不能宣称具有安全凭据存储能力。

执行记录作为不可信内容显示，Markdown 和 HTML 展示进行限制，日志中的命令和链接不会自动执行。渲染层通过受控 preload 接口访问功能，启用上下文隔离和适当的 CSP；Go 接口验证来源范围和参数。[Electron 安全指南](https://www.electronjs.org/docs/latest/tutorial/security)

导出前预览内容及附件范围，允许移除选定内容并检查常见密钥。自动脱敏不能保证识别所有敏感信息。默认导出当前标准化记录和选中的分析，原始附件由用户明确选择。

### 中间版本与最终交付门槛

**本地预览（A–E）**：在无 Go/Node 的 Windows 环境安装 → 发现并确认真实记录 → 重启仍可浏览 → 更新已登记记录 → 查看工具和来源证据 → 标注/手动对比 → 导出并在空白任务库再次导入。全程不依赖模型密钥；真实版本支持范围与已知限制随包提供。它是内部试用门槛，不等于公开 Alpha。

**公开 v0.1 Alpha（F）**：本地预览能力、可选 Jev 两个检测器、质量报告、许可证和最终安装/升级验证齐备。若 Jev 质量不足，保持本地预览，不把缺项版本改称已达到 Alpha 目标。

**跨 harness 最终产品（G–I）**：支持矩阵中的多个 harness 有真实轨迹与端到端证据；Langfuse 和 Harbor 在声明的版本/格式/评测范围内实际互操作；部件分析通过预先定义的质量标准，比较能复现控制条件与不确定性；eval 可选择 Jev，原生评分不被替换；最终安装升级和完整 UI 验收通过。该目标是必交范围，不因完成 Codex Alpha 而终止，也不把未声明的任意来源算作已支持。

### 主要风险与处理顺序

| 风险 / 依赖 | 处理与继续工作的边界 |
| --- | --- |
| 真实兼容证据不足 | 一份 0.160.0 记录不能覆盖全部工具和模式；样本可保持私有本地验证，仅获准公开的脱敏内容入库。缺样本不阻塞合成回归，但阻塞相应兼容声明 |
| 身份与快照耦合 | 已增加快照身份和证据绑定；当前事件 ID 仍为路径身份加物理行号。后续标注/分析必须使用快照加事件的组合引用，不能直接把事件 ID 当永久证据 |
| paginated 归一化需要全局信息 | D01 在前缀或后缀出现 item_completed、未关联工具结果等情况时完整重算；安全前缀才续接解析，与完整重读比较，不盲目追加事件 |
| 数据规模与正文丢失 | D02 另存标准化正文并按需分页，旧记录可能缺失；D03 用固定样本测量后扩容。搜索、交换与 Jev 输入必须声明实际范围；当前搜索/交换仍限预览 |
| 分发与外部决策 | A 提前暴露安装/驱动问题，F 复验最终包；作者在公开发布前确定许可证。缺环境或许可证记录为明确依赖，不反复改 UI 代替完成 |

## 测试与发布验收

测试重点应放在真正可能损坏记录、误导用户或中断体验的行为上。

| 范围 | 必须验证的行为 |
| --- | --- |
| 数据适配 | 不完整记录、未知字段、版本变化、工具结果关联和分支关系 |
| 增量同步 | 重复扫描、追加半行、轮转、截断、异常中断和恢复 |
| 跨进程通信 | 分包、并发请求、取消、错误响应、引擎退出和协议不兼容 |
| 桌面流程 | 扫描、打开、搜索、分析、跳转证据、标注与导出 |
| 分析 | 模拟服务下的错误处理；真实服务下的留出样本评估 |
| 分发 | 打包路径、带空格与中文的路径、用户目录权限和应用升级后的数据迁移 |

D03 已先测旧配额合成基线，再测 1000 条任务及单记录 10000 个事件；总当前事件仍限 50000。门槛保留为已有索引下三秒内可操作、首屏查询与展示 P95 不超过一秒、取消后一秒内显示反馈；10 次新进程启动、20 次热首屏和分页、内存工作集/峰值与真正停止/落盘耗时均保留原始测量。进程冷启动不等于清空 OS 文件缓存；本轮不做后者。固定样本生成规则、产物摘要、设备环境、实测和限制见 [规模验收](development/library-scale.md)，不能据此承诺所有真实正文/元数据/历史库分布的性能。

每次验收记录提交或产物版本、日期、环境、样本性质、实际命令/人工步骤、结果与未覆盖范围。源数据不变、旧快照保留、证据正确与往返一致是数据链路的优先门槛；远程 CI 以实际检查记录为准。本轮 A 切片验证记录见 M0 进度。

首版发布前必须确认：基础浏览不需要 Jev；未知指标未显示为零；重复扫描无重复事件；原始记录未被修改；诊断能定位真实证据；导出可重新读取；安装包不需要 Go、Node 或开发 IDE。Electron 的打包与分发需包含配套资源，并按首发平台验证签名或未签名状态的呈现，不能把未经验证的构建标为正式支持。[Electron 打包文档](https://www.electronjs.org/docs/latest/tutorial/application-distribution)

## 后续版本方向

Alpha 后按 G–I 和 feature-list 继续实现 ATIF、多 harness、Langfuse/Harbor 互操作及成熟分析验证；这些已由用户明确为最终范围。每个来源和版本独立确认格式、样本与验收，版本号随实际能力决定。文件监听仅作为已可靠的手动更新链路的触发器追加。

主动采集组件可提供本地 HTTP 接收端和轻量 SDK，使自定义 harness 发送统一事件。独立常驻、远程采集与 OpenTelemetry 支持各自评估需求，不因接口预留而全部实现。

Harbor 运行衔接记录模型、harness 配置、环境、预算、任务版本和重复次数，比较同一条件下的策略变化。任务原生 verifier 与 Jev 过程诊断分开展示。2026-10-07 核对的 Harbor Rewardkit 文档包含 Jev judge；实际 ATIF 输入及评分能力须在实施时锁定版本并测试，不能从存在 judge 选项推导 jeval 已兼容。[Harbor judge 文档](https://docs.harborframework.com/rewardkit/judge-criteria)
