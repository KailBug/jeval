# jeval 项目开发规划

规划日期：2026 年 10 月 3 日\
最近更新：2026 年 10 月 4 日\
文档状态：M0 开发中，尚未完成验收（见 [M0 进度](development/m0-progress.md)）\
适用对象：项目作者与后续开源贡献者

jeval 是面向 Agent 和 harness 开发者的桌面工作台。它将不同来源的执行记录汇集到本地，提供统一浏览、证据检查、记录对比和导出，并允许用户按需启用 Jev 分析。长期目标是帮助开发者评估 harness 改动是否有效。

开发采用 Electron 与 TypeScript 构建桌面应用，使用 Go 实现独立采集引擎。第一版先交付“发现任务、查看记录、按需分析、导出”的完整流程，再扩展实验执行与回归评测。

## 当前实现状态

截至 2026-10-04，已打通 Electron + React → preload → 主进程 → Go 引擎的浏览链路，并验证 Windows 目录包携带引擎运行。除三条合成演示外，现已实现显式选择经典 Codex rollout JSONL 文件、只读导入、来源筛选、时间线与实际文件行号定位；尚未用真实脱敏样本验证版本兼容性，不调用 Jev。

首个本地来源已由用户确定为 Codex。Windows 是当前验证平台，尚未完成安装包与干净环境验收。M0 仍缺真实脱敏样本、来源映射验证、完整关键页面原型及部分技术决策；M1 只有基础浏览界面，不能视为已完成。

本文后续的“首版范围”“实施要求”和“验收”均为目标要求，不代表已实现。当前代码职责见 [M0 架构](architecture/m0-architecture.md)，操作入口见 [开发运行指南](development/getting-started.md)，全部文档见 [文档索引](README.md)。

## 用户与核心使用场景

第一批用户是个人 Agent 开发者、harness 作者，以及需要检查本地 Agent 执行记录的工程师。

| 场景 | 用户的问题 | 产品应交付的结果 |
| --- | --- | --- |
| 查找任务 | 上次运行的记录在哪里 | 按来源、项目和时间组织的任务列表 |
| 复盘失败 | 为什么反复尝试仍然失败 | 可展开的执行时间线和可定位的原始证据 |
| 检查完成情况 | 最终回复与实际执行是否一致 | 验证结果、产物信息与完成声明的并列查看 |
| 比较改动 | 两次运行具体哪里不同 | 元数据、指标、执行记录的并排对比 |
| 分享问题 | 怎样让别人复现或理解问题 | 带版本和来源信息的记录包、诊断与人工标注 |
| 后续评测 | 某项 harness 策略是否有效 | 在控制实验条件下运行任务并比较结果 |

“导入”指将已有数据登记或复制到 jeval；“导出”用于备份、分享或外部使用。用户查看和分析记录时，不需要先手动导出再重新导入。

## 第一版范围

首个公开版本建议命名为 v0.1 Alpha。它需要完整支持一种常用本地 harness，并支持明确版本范围内的 Harbor ATIF 文件或结果目录导入。

| 能力 | 首版交付范围 | 验收要点 |
| --- | --- | --- |
| 开箱演示 | 内置明确标识的脱敏演示记录及预存分析 | 无密钥也可体验，不将演示结果伪装成当前模型调用 |
| 本地发现 | 常用记录目录与用户添加目录 | 扫描可取消；能看到来源、进度、失败项 |
| 任务库 | 来源、项目、时间、状态筛选及文本搜索 | 未知状态和缺失数据有明确展示 |
| 统一查看 | 消息、工具调用、结果、错误、验证与分支关系 | 每个标准化事件可追溯到原始来源 |
| 增量同步 | 更新已登记记录 | 重复扫描不重复建任务；支持重启后继续 |
| Jev 分析 | 用户主动触发，两类检测器 | 可关闭、取消；结果附证据、版本和分析范围 |
| 人工标注 | 接受、否定、待确认和备注 | 人工意见与模型结果分别保存 |
| 基础对比 | 两份记录并排查看和指标对比 | 支持手动选定对比记录；不按相同步骤编号强行对齐 |
| 导出 | 统一记录 JSON 和便于阅读的 Markdown 报告 | 导出说明缺失字段、快照范围与模型诊断性质 |
| 安装运行 | 一个验证过的首发平台 | 安装包携带 Go 引擎，用户无需安装开发工具 |

首版暂不承担跨平台全部适配、自动修改代码、自动停止 Agent、云端团队协作、完整实验调度、自动优化 harness、公开排行榜和多模型分析后端。它们应以独立里程碑进入后续版本。

## 首次使用与日常流程

首次打开时，用户可以先浏览演示，也可以点击“发现本地任务”。扫描范围显示为具体来源和目录，用户可增删目录。扫描先建立轻量索引，选中任务后加载详细内容。

任务库按项目和来源组织，支持最近更新、错误状态和手动收藏。来源记录无法确定是否结束时显示“状态未知”；正在追加的记录显示“更新中”，不据此推断 Agent 已成功或失败。

打开任务后，用户可以搜索消息，展开工具参数与结果，跳转错误或验证步骤。点击“使用 Jev 分析”后，选择检测器和分析范围，查看将发送的内容，再发起本次分析。分析在后台执行，基础浏览保持可用。

用户可以在诊断上添加意见，选择另一份记录比较，或者导出当前快照和报告。删除 jeval 内的索引、快照或分析结果，与删除原始 harness 文件是不同操作；首版只提供前者。

## 界面与视觉验收

视觉设计在开发早期完成，并贯穿每个里程碑。优先验证高信息密度下的可读性、层级和操作反馈。

| 页面 | 主要内容 | 关键交互 |
| --- | --- | --- |
| 欢迎与数据来源 | 演示、本地来源、导入入口 | 一键发现、添加目录、查看适配状态 |
| 任务库 | 项目分组、任务列表、筛选与搜索 | 多选、排序、打开任务、导出 |
| 执行详情 | 左侧导航、中间时间线、右侧检查面板 | 展开工具、跳转证据、查看原始记录 |
| 分析结果 | 检测器结果、证据位置、人工反馈 | 接受或否定诊断、重新分析 |
| 记录对比 | 两份记录、关键指标与差异 | 手动定位对应片段、独立滚动 |
| 设置 | 来源目录、Jev、存储与应用信息 | 连接测试、配置开关、清理本地缓存 |

先设计任务库、执行详情和对比页的关键状态，使用真实长度的日志和工具输出验证布局，再扩展其他页面。

视觉验收要求：

- 统一字体、字号、间距、颜色、圆角和状态组件；状态同时提供文字，不能只靠颜色区分。
- 完整覆盖空数据、加载中、部分失败、无密钥、不支持格式、记录缺失和分析取消状态。
- 长文本按需展开，工具输出使用虚拟列表或分页；避免一次渲染全部记录。
- 支持键盘导航、可见焦点、可调整面板宽度及减少动态效果的系统偏好。
- 检查至少两种窗口尺寸与首发系统的常用缩放比例，验证中文、英文和长文件路径。
- 首版优先打磨一套主主题，并预留主题变量；第二套主题在不影响核心交付时加入。

## 技术结构与职责

| 模块 | 建议技术 | 职责 |
| --- | --- | --- |
| 桌面渲染层 | TypeScript 与 React | 任务库、时间线、对比和状态交互 |
| Electron 主进程与 preload | TypeScript | 窗口、文件选择、受控 IPC、凭据访问和 Go 进程生命周期 |
| 采集核心 | Go | 扫描、读取、解析、转换、增量同步、查询和导出 |
| 来源适配层 | Go | 屏蔽不同来源的数据格式与获取方式 |
| 分析模块 | 建议放在 Go 独立包 | 规则检测、Jev 调用、任务队列与结果归档；不与采集逻辑耦合 |
| 存储 | 建议 SQLite 与独立快照文件 | 索引、标准化事件、分析、标注、同步进度及原始数据快照 |

Go 引擎编译为独立可执行文件，随应用分发，由 Electron 主进程启动。首版与应用同生命周期；独立常驻模式放到后续。Electron 主进程运行于 Node.js，可通过其子进程能力启动可执行文件，渲染层通过 preload 暴露的有限接口调用业务功能。[Electron 进程模型](https://www.electronjs.org/docs/latest/tutorial/process-model)、[Node 子进程文档](https://nodejs.org/api/child_process.html)

建议在同一仓库中维护桌面端、Go 核心、数据与通信协议、样本、文档和 CI。统一记录 schema 与通信协议单独版本化，并使用同一份样例验证 TypeScript 和 Go 的解释一致。

## 数据模型与来源适配

首版使用小而明确的内部模型，保留源格式的扩展字段。统一展示不等于所有来源拥有相同的信息。

| 实体 | 主要信息 |
| --- | --- |
| Source | 来源类型、位置、原始版本、适配器版本、同步状态 |
| Project | 项目名称、路径或来源项目标识 |
| Session | 会话标识、标题、项目、父子或分支关系 |
| Run | 一次执行或快照、来源标识、模型与 harness 元数据、可用指标 |
| Event | 消息、调用、结果、错误、验证、时间戳、顺序与父子引用 |
| ArtifactRef | 产物位置、类型、快照状态及可用性 |
| Finding | 检测器、结论、概率或分数、证据事件、分析版本与覆盖范围 |
| Annotation | 用户意见、备注、时间与关联对象 |

不同来源未必区分 Session 和 Run。适配器应记录映射依据，不将任意一次对话自动解释成独立实验。并行调用、子 Agent 与会话分支保留关系，时间未知时不能伪造时间戳。

每次归一化记录来源 ID、文件位置或远程定位信息、适配器版本和快照摘要。重复导入按来源身份和内容版本去重；跨平台来源之间只标记可能重复，避免自动合并不同执行。

ATIF 是首版的外部交换格式之一。Harbor 已定义轨迹中的消息、工具调用、观察结果和指标，jeval 应说明支持的 schema 版本及扩展字段处理方式；只有实际输出这些数据的 Agent 才能提供对应能力。[Harbor ATIF 文档](https://docs.harborframework.com/core-concepts/agents/atif)

后续 Langfuse 连接器通过用户配置的实例与凭据读取数据，并保留 observation 的父子关系。实现时按实例版本选择可用 API，采用时间范围和分页，不能把“本地扫描”包装成自动发现远程项目。[Langfuse 公共 API](https://langfuse.com/docs/api-and-data-platform/features/public-api)

## Go 采集引擎实施要求

来源适配器应表达自己支持发现、列出任务、读取、增量更新还是远程获取。首版可先实现具体适配器，再抽取有实际复用价值的公共接口。当前 Codex 已实现用户选定 JSONL 文件的只读解析，格式子集、合成验证与待验收内容见 [适配器说明](adapters/codex.md)；目录发现、持久化和增量更新仍未实现。

采集流程包括目录发现、任务索引、事件解析、格式转换和事务写入。首次扫描与增量扫描分别记录进度。文件监听作为更新提示，结合检查点和补扫恢复，不能假定每次文件变化都会收到通知。

需要覆盖以下行为：

- 半行 JSON、追加写入、截断、轮转和文件替换均不会导致永久停止同步。
- 一个坏文件或无权限目录产生独立错误，其他来源继续处理。
- 并发数、队列和单条事件大小有上限；扫描、读取和导出支持取消。
- 读取数据库或其他结构化存储时采用该来源适合的一致性方式，不修改原始记录。
- 所有数据库写入由 Go 管理；大段内容按需读取，界面使用分页查询。
- 检查点与数据写入保持一致，重复处理允许去重，重启后不丢失已确认的数据。
- 本地存储迁移、备份和可恢复失败有明确流程。

主动采集属于后续版本：在同一核心上增加可选 HTTP 接收端，允许其他语言通过 SDK 或 hook 上报事件；必要时增加 OpenTelemetry 接收适配。它不能恢复历史上未被记录的工具调用或模型信息。

## 桌面通信与进程管理

首版建议采用标准输入输出上的逐行 JSON 协议。请求、响应和通知分别带类型；请求包含 ID 和协议版本；响应返回结果或结构化错误；通知承载扫描进度和任务更新。

握手返回引擎版本、协议版本和可用能力。普通调试日志写入 stderr。大型轨迹按页查询或通过受控文件引用传输，避免将整段日志放进一条消息。更新通知可以合并，避免界面处理不过来。

Electron 管理启动、就绪、退出和异常状态。Go 退出后，界面应显示恢复入口；重连后重新查询未完成任务，不自动重复非幂等操作。关闭应用时先请求取消与落盘，再在限定时间后结束进程。

## Jev 分析设计

Jev 开关从第一版进入产品设计。默认基础功能不依赖 API key；用户主动启用后才执行远程语义分析。关闭开关停止排队任务，并尽可能取消进行中的请求；已经发送的内容无法通过取消撤回。历史结果继续可读。

首版保留两类语义检测器：

| 检测器 | 输入与问题 | 结果边界 |
| --- | --- | --- |
| 无效重试 | 相邻尝试、错误、状态变化与新增证据；是否反复执行实质相同的无效策略 | 输出疑似片段与证据，区分合理重试和探索 |
| 完成证据一致性 | 最终声明、最近相关验证和产物信息；声明是否受到记录支持 | 区分受到支持、证据矛盾、证据不足 |

退出码、完全相同的调用、耗时和数量由代码计算。Jev 处理剩余的语义问题。类型化判断与概率是 Jev 的接口能力，但模型概率不是事实证明。[Jev 官方文档](https://docs.typesafe.ai/introduction)

使用相关片段而非无条件发送整段轨迹；保留事件 ID、截取规则和覆盖范围。输入过长时显式分段或报告无法分析，不静默截断关键证据。首版优先按单项声明或片段判断，再由代码汇总；泛化的长篇解释不是必需能力。

每次分析记录输入摘要、来源快照、模型返回版本、检测器与问题版本、阈值版本、耗时、用量和实际错误。缓存键包含这些影响结果的因素；复用结果必须标记缓存状态。无法取得的费用标为未知，估算费用标记计算口径。

用户标注不覆盖模型原始结果。检测器变更后旧结果标记版本差异，重新分析由用户发起。Jev 错误、超时和证据不足应独立呈现，不能被解释为通过检查。

## 诊断质量与评测方法

首版先构建一组有人工标注的真实脱敏轨迹片段，并补充明确标为合成的边界用例。建议从每类检测器数十个样本起步，用于暴露问题，不据此宣称普遍有效。

样本需包含正常探索、合理重试、无效重试、验证通过、验证失败和证据缺失。按任务或项目划分开发集与留出测试集，避免同一次运行的相邻片段分散到两边。问题和阈值在开发集上调整，测试集用于最终报告。

对比纯规则、规则加 Jev，以及资源允许时的普通 LLM 判断。报告每类检测的误报、漏报、精确率、召回率、无法判断比例和覆盖率；同时记录分析费用、端到端延迟和样本量。评估器自身超时与程序错误单独统计。

用户界面用“疑似问题”呈现尚未人工确认的诊断。离线发现重复尝试不等于已经证明能够节省 token 或提高成功率；这类收益需要后续实际干预实验验证。

## 数据处理与桌面边界

扫描范围限定于已适配来源的常用目录和用户添加目录，发现与浏览保持本地处理。Jev 分析明确展示输入范围；远程数据连接和分析各有自己的开关。

凭据通过系统凭据存储或经过验证的桌面加密存储方案管理，不写入普通日志、导出包或默认配置文件。未验证的平台不能宣称具有安全凭据存储能力。

执行记录作为不可信内容显示，Markdown 和 HTML 展示进行限制，日志中的命令和链接不会自动执行。渲染层通过受控 preload 接口访问功能，启用上下文隔离和适当的 CSP；Go 接口验证来源范围和参数。[Electron 安全指南](https://www.electronjs.org/docs/latest/tutorial/security)

导出前预览内容及附件范围，允许移除选定内容并检查常见密钥。自动脱敏不能保证识别所有敏感信息。默认导出当前标准化记录和选中的分析，原始附件由用户明确选择。

测试重点应放在真正可能损坏记录、误导用户或中断体验的行为上。

| 范围 | 必须验证的行为 |

| 分析 | 模拟服务下的错误处理；真实服务下的留出样本评估 |
| 分发 | 打包路径、带空格与中文的路径、用户目录权限和应用升级后的数据迁移 |

建议建立固定性能样本集，记录测试设备、系统和应用版本。初始目标包括：已有索引下应用在三秒内可操作；一千条任务的首屏查询与展示 P95 不超过一秒；一万事件记录按需展开时保持流畅；界面在取消操作后一秒内更新状态。它们是待验证的目标，M0 和 M1 建立基线后调整，并同时记录引擎停止与落盘的耗时。

首版发布前必须确认：基础浏览不需要 Jev；未知指标未显示为零；重复扫描无重复事件；原始记录未被修改；诊断能定位真实证据；导出可重新读取；安装包不需要 Go、Node 或开发 IDE。Electron 的打包与分发需包含配套资源，并按首发平台验证签名或未签名状态的呈现，不能把未经验证的构建标为正式支持。[Electron 打包文档](https://www.electronjs.org/docs/latest/tutorial/application-distribution)

## 后续版本方向

v0.2 优先考虑 Langfuse 连接、第二个本地适配器、完善语义对比，以及把选中片段保存为评测样本。根据实际反馈选择其中最有用的部分。

主动采集组件可提供本地 HTTP 接收端和轻量 SDK，使自定义 harness 发送统一事件。独立常驻、远程采集与 OpenTelemetry 支持各自评估需求，不因接口预留而全部实现。

后续完整评测版本再接入 Harbor 任务运行，记录模型、harness 配置、环境、预算、任务版本和重复次数，比较同一条件下的策略变化。任务的原生 verifier 与 Jev 过程诊断分开展示。Harbor 已提供 Jev judge，但当前文档列明该后端不支持直接使用 ATIF 轨迹；这一能力可以评估复用、外部扩展或上游贡献，不能当成现成支持。[Harbor Jev judge 文档](https://docs.harborframework.com/core-concepts/rewardkit/judge-criteria#jev-judge)
