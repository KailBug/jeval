## C：单快照导出与再导入

本轮实现一个已保存、非演示 Codex 快照的原生 JSON 和 Markdown 导出。导出取数据库中的完整当前快照，与页面搜索、类型筛选和分页无关，原始 JSONL 离线不影响导出。交换格式 v1 与记录 schemaVersion=1、协议 v1、SQLite 布局 v3 独立版本化，定义与共享合成样本见 [交换契约](../../contracts/exchange/README.md)。

- 包明确包含标准化预览，不含原文件；正文预算为 8192 字节，既有截断提示另计。保留事件、父关系、原始定位、来源摘要、适配器版本与快照身份。未知指标和时间保持 null，不补造成功状态或模型诊断。
- 导入只读取用户选择的包，严格校验版本、字段、数量、内容预算和引用关系，不访问包中的来源路径。新来源保存为只读交换记录，重启保留；相同当前快照重复导入幂等，同来源不同当前快照拒绝冲突，不悄悄回滚或覆盖。
- 本地来源更新权限独立于不可变快照内容：SQLite v2→v3 增加授权状态，原有来源保持可更新。包不能授权访问旧路径；用户通过 Codex 选择器或确认扫描重新绑定本地来源后才可更新。回导同一包不取消原库已有授权。
- 主进程控制打开/保存选择器，渲染层只提交记录 ID 和格式。界面展示当前快照事件总数、正文和来源路径范围、没有原文件和自动脱敏。取消选择不调用写入或导入；成功只在实际文件替换或事务提交后显示。
- 文件输出先在目标目录写临时文件、同步并替换，失败清理临时文件并保留旧目标。拒绝数据库及旁路文件、已登记原来源、链接和特殊目标。Markdown 将来源正文放入动态长度的围栏，不将日志内容执行为 HTML 或命令。

## PR #8 的 Windows CI 路径断言修复

2026-10-05，[Actions 失败记录](https://github.com/KailBug/jeval/actions/runs/37313255054) 在 `npm run check` 的交换集成测试失败：Markdown 来源路径与测试的原始 `source` 字符串不一致。该次环境为 Windows Server 2025、Node.js 24.21.0、Go 1.26.0；Go 测试和其余 10 项集成测试通过，后续 E2E 与打包步骤未执行。

Codex 导入先通过 `filepath.EvalSymlinks` 保存实际来源定位，Windows 会规范化路径大小写和目录别名。Actions 临时路径包含 `RUNNER~1` 短目录名；原始选择字符串不是已保存定位的可靠预期。本机将 `TEMP` 改为不同大小写后复现了相同的 Markdown 断言失败。问题属于本次新增测试的路径假设，生产导入/导出逻辑和 CI 工作流无需改动。

交换集成和桌面 E2E 现在显式通过不同大小写的 Windows 路径选择同一合成来源，并确认保存定位与选择字符串不同；Markdown、导出范围及离线恢复后的证据均按 `importInfo.file` 核对。完整 JSON 和事件往返比较仍保留。失败输出检查同时改为匹配实际临时文件前缀 `.jeval-export-`。

修复后本机 Windows x64、Node.js 24.19.0、Go 1.27.0、Electron 44.5.1 验证：`npm run check` 通过（含 11 项集成测试），开发版和重新打包后的目录包各 6 项 E2E 通过（均 21.8 秒），`npm run pack` 与随包引擎的 `npm run test:storage` 通过。修复提交的远程结果以 [PR #8 检查记录](https://github.com/KailBug/jeval/pull/8/checks) 为准，本机通过不代替远程运行。本轮只使用合成样本，不提升真实来源、安装或里程碑验收状态。
