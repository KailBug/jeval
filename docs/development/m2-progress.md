## D01 交付时的实现

已登记 Codex 记录通过后台任务更新，界面显示核对/处理状态，可取消，任务结束后刷新已保存快照。读取与解析不持有协议服务锁，期间可查询旧版本；提交与取消共享锁，取消先被接受则不再提交，提交已完成则返回完成状态。异常或重启恢复已提交快照，未完成工作不会伪装为成功；重启后可再次手动更新。

检查点绑定来源、快照、适配器版本和源摘要；SQLite 布局 v4 将检查点、当前指针、快照和派生索引放在同一事务中。v3 升级保持原快照和只读权限，无旧检查点时完整解析并建立缓存。缓存损坏回退完整解析，数据库读取错误显式失败。只读交换来源不能更新，检查点不进入交换包。

每次仍读取整个有界源文件并计算摘要；仅优化 JSON 解析和归一化，不宣称减少磁盘读取或达到性能目标。前缀字节一致、以换行结束、已有事件且没有投影/未关联工具结果时，续接新行、工具关联和标题状态；所有证据重新绑定新快照。源字节未变则复用旧快照，解析行数为零。

截断、重写、无末尾换行、前缀含 item_completed、后缀新增投影、未关联工具结果或检查点失效时，回退完整双遍解析。后到 canonical 消息因此可纠正旧投影；半行补全会重新解析半行所在快照。报告区分 full/incremental/unchanged 和回退原因，定义见 [协议](../../contracts/protocol/README.md)。保持 `codex-rollout-v1` 的归一化、8 KiB 预览和来源/快照身份语义。
