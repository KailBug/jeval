# 阶段自动开发流程

更新日期：2026-10-07。状态：P00 建立的仓库执行约定；不是已部署的定时调度服务。当前功能及授权以 feature-list 和用户本轮指令为准；D01 已合并，本轮为 A01；后续 PR 使用英文，分支使用 feat/ 等非 codex/ 前缀。功能入口为 [feature-list](../../doc/feature-list.md)，方向以 [主规划](../jeval-development-plan.md) 为准。

## 交付与授权单位

M0–M8 和 A–I 表示能力里程碑与工作切片，不等于一次自动运行。每次授权只推进清单中一个可独立验收的功能点，串行完成一个 PR。大功能在编码前拆出有用户可见结果和完整验收链路的任务；不得把仅能编译的中间层当成功能端到端完成。

状态依次为：待授权 → 开发中 → 验证中 → PR/CI 中 → 已合并、待同步 → 已同步、等待继续。实际阻塞另记原因。状态判断结合清单、Git、PR 和 CI，不仅相信上次聊天的完成声明。功能已合并不等于整个产品里程碑通过。

用户一次“继续”或等价指令只授权下一项。每次 merge 后完成本地同步和交付报告就停止，不提前创建下一分支、编写下一功能或消费未来阶段授权。恢复中断时先核对现有 PR：未合并则继续同一阶段；已合并则只补同步和报告，没有新的“继续”就不能开发下一项。

## 在现有目录执行

1. 阅读 AGENTS、文档索引、主规划、feature-list 和所属阶段进度；检查工作区、当前分支、远程状态和已有 PR。存在其他任务或用户未提交修改时保留现场，不切换覆盖，不自动 stash。
2. 确认当前阶段授权、依赖和验收标准。无活动功能时，从已同步的 main 创建 `feat/<编号>-<描述>`；不得新建 `codex/` 前缀分支，已有本阶段分支/PR 时复用。不创建 worktree，不并行开展其他功能。
3. 实现当前功能并同步受影响的契约、设计、适配器、运行和进度文档。必要的契约变化以 contracts 为准，不在清单复制字段定义。
4. 验证用户完整流程和故障行为，审查差异与范围；失败在原分支修复。记录命令、环境、样本性质、结果、未覆盖范围和对应版本。
5. 提交、推送并创建或更新一个 PR。后续 PR 标题和描述使用英文，写明行为变化、实际验证、限制和任务编号；不提交私人原始轨迹或凭据。历史 PR 不追溯改名。
6. 跟进最新 head 的远程 CI。对实际失败分析后修复，不把环境失败写成应用通过；推送新提交后重新核对受影响的本地检查和最新 CI。
7. 阶段验收、必要 CI、仓库要求及阻塞审查项均满足时，按已授权范围合并。合并操作应绑定已检查的 head SHA；若 main 变化影响验收，则先同步并重验相关内容。
8. 确认无未提交修改，执行下列命令并核对本地 HEAD 与远程 main 及合并结果。失败不强制覆盖，保存原因；成功后报告 PR、验证、限制和下一候选，等待用户“继续”。

```powershell
git switch main
git pull --ff-only origin main
```

清单与进度在 PR 中记录该交付分支已完成的事实和 PR 链接。CI 结果、合并时间及合并提交以 GitHub 为准；不得在尚未合并的提交中声称已合并。下次获授权时对账、补记上阶段结果，避免为了更新一个状态在 merge 后继续修改 main。即使清单仍写“PR 中”，远程已合并也必须进入等待继续状态。

## 验证与合并门槛

- 纯文档功能：检查本地链接、引用命令、功能依赖、文档范围及格式，运行 `git diff --check`；不为此在本机重跑无关应用测试。现有 CI 若自动触发完整测试，仍须等待其实际结果。
- 应用功能：按变更执行类型、Go、跨进程和桌面验证；桌面流程变更需验证实际 IPC/引擎路径及最终目录包。命令以 [运行指南](getting-started.md) 和 package.json 为准。
- 安装、真实来源、远程 API、迁移及规模有各自验收环境。现有本地环境获准使用，不等于已证明干净安装或上游兼容通过。缺少必要环境时不得合并声称完成该验收的功能。
- Jev 和兼容评测须有真实接口/格式证据、版本及质量报告；模拟服务和合成样本单独记录。不能以模型自己给出的“通过”替代数据、产物和 CI 检查。
- 不删除有效测试或降低阈值来获得绿灯；修正错误测试预期须保留复现证据。无必要检查记录、仍运行、取消或失败均不算通过；仓库要求的审核和保护规则不得绕过。
- 不设置人为用量或失败次数上限。遇到额度、权限、凭据、环境或产品决策阻塞，明确记录并报告；根据新证据重试，不无限重复同一操作。可恢复的当前阶段工作继续完成。

## 样本与证据

优先检索官方仓库、公开数据集和开放评测轨迹，记录下载 URL、固定版本或提交、摘要、来源许可证/使用条件、格式版本、场景和验证范围。公开可读不自动等于可再分发；不确定能否公开时仅保存允许公开的元信息，采用本地验证或合成回归样本。

允许只读使用本地至少三个月前的历史轨迹，限定在相关 harness 的记录目录，不扩大到无关私人文件。每阶段记下执行日期和按三个日历月计算的截止日；2026-10-07 对应 2026-07-07 之前。以轨迹中的会话/事件时间核对，持续更新到近期的旧会话不能仅凭创建时间入选；日期无法确认时暂不选用。

本地原件只读，测试使用独立临时资料库，验证前后核对源摘要。私人内容不进入 Git、PR、截图或公开测试产物。远程 Jev 调用须满足该评测的输入范围与数据使用授权，旧数据授权不包含默认上传私人内容。没有可用旧样本时继续寻找公开轨迹，不能扩大到近期私人数据。

## 长期运行边界

本约定由当前获授权的开发会话执行；本阶段不创建定时任务、后台守护进程、外部执行器或自动合并工作流，也不声称应用关闭后仍会运行。中断可从 Git、PR、清单和阶段进度恢复。未来若增加调度器，仍必须满足现有目录单写者和每次 merge 后等待用户“继续”的规则。
