# D03 任务库规模验证

更新日期：2026-10-08。D03 将任务库扩展到 1000 个已导入来源、单记录 10000 个事件；总当前事件仍限 50000（协议层含演示）。本页记录规模依据，不扩大 [Codex 真实来源矩阵](../adapters/codex-source-matrix.md)，也不代替 A02 干净 Windows 安装验收。

## 范围与配额

| 项目                    | D02 基线        | D03   |
| ----------------------- | --------------- | ----- |
| 已导入来源              | 20              | 1000  |
| 单记录事件              | 5000            | 10000 |
| 当前事件总量            | 50000           | 50000 |
| 单源文件 / 行数         | 16 MiB / 50000  | 不变  |
| 单事件 / 单快照完整正文 | 16 MiB / 32 MiB | 不变  |
| 单次正文读取            | 32 KiB          | 不变  |
| 扫描单批候选 / 保存目录 | 200 / 20        | 不变  |

Go 容量常量集中在 [model/limits.go](../../engine/internal/model/limits.go)，适配器、交换、协议预检/恢复和存储共同使用。SQLite 保持 v5，protocol/record/exchange 保持 v1；这是容量放宽，未修改字段或证据身份。旧版本可能拒绝扩容后的库或超过 5000 事件的交换包，不承诺降级兼容。历史快照和正文不包含在 50000 当前事件限额内；本阶段没有磁盘总配额和历史清理。

## 可复现方法

[测量脚本](../../scripts/validation/library-scale.ts) 使用真实目录包 Electron → IPC → Go → SQLite，在 `.local/scale-*` 创建独立资料库及合成来源，结束后仅清理自己的临时目录。不安装应用，不读取用户轨迹或已有资料库。

`library-scale-v1` 固定生成混合消息、工具调用及结果，并在每条任务末尾放入超过 32 KiB 的中文/emoji 正文。基线为 20 条任务：1×5000＋19×2000＝43000 事件；目标为 1000 条任务：1×10000＋999×40＝49960 事件。报告包含字节数、样本聚合 SHA-256、数据库大小、环境及实际引擎/EXE/asar 摘要。两个数据集不同，结果用于各自门槛验收，不作为同工作负载加速比。

- 导入后核对数量、全部任务分页、最大记录的全部事件顺序/行号/快照/工具父关系，以及最大记录预览交换到空库。
- 移走全部来源后启动 10 个全新应用进程，每次测量启动至引擎已连接且来源按钮可用；保留首次和后续原始样本。没有清空 Windows 文件缓存，不能称为 OS 冷缓存测试。
- 在最后一个进程中进行 20 次任务首屏、事件首屏和真实 IPC 热查询；首屏包含点击、查询、DOM 断言及两次动画帧。P95 使用排序后 `ceil(N×0.95)` 的样本。任务首屏保持 10 项、事件页 50 项。
- 连续翻过 20 个事件页并滚到页尾，核对序号与 DOM 数量；搜索最大记录末尾证据并读取完整正文。另搜索第 1000 条任务并浏览。
- 给脚本自己生成的来源追加有界忽略行，通过真实 UI 开始更新并取消。分别测量“正在取消”反馈及“更新已取消”终态；确认旧快照未改变。后者为引擎终态到 UI 可见的延迟，不是采样 CPU 停止时间。
- 记录实际引擎退出、应用关闭耗时，关闭后重新打开 SQLite 核对旧快照；恢复测试文件后逐份核对原始字节摘要。
- 记录导入 Go 进程、浏览前后和取消后的 Electron 各进程与 Go 工作集、生命周期峰值。各进程峰值发生时间可能不同，不能相加冒充同时发生的应用峰值；不是完整堆增长或长时间泄漏证明。

验收门槛为每次索引后启动≤3000 ms、任务和事件首屏 P95≤1000 ms、取消反馈≤1000 ms。内存和实际结束时间如实报告，未虚构原规划没有指定的内存阈值。脚本正确性断言或性能门槛失败均退出非零；CI 上传 `library-scale-evidence` 原始 JSON。

在仓库根目录运行：

```powershell
npm run pack
$env:JEVAL_PACKAGED_EXECUTABLE = (Resolve-Path 'release/win-unpacked/jeval.exe').Path
node --import tsx scripts/validation/library-scale.ts target .local/library-scale.json
```

`baseline` 模式运行相同生成器的旧规模。历史 D02 基线使用当时的目录包；在 D03 上重新运行 baseline 只能得到新版本的小规模结果，不能替代旧版本基线。

最终目标运行已核对全部 1000 条任务无重复/遗漏、10000 事件的分页和证据、末条任务搜索、长正文、最大记录交换、源离线 10 次重启、取消后重开旧快照及来源摘要。基线报告早于脚本新增完整任务分页、末条任务 UI 和源码身份元数据，不追补未经当时记录的脚本摘要；样本生成器、原始测量及产物摘要保留原样。

## 限制

这是指定 Windows 开发机、固定合成分布、目录包的有限验证。10 次启动和 20 次首屏不能推出所有硬件、最大正文组合、任意搜索分布或无限历史都满足相同性能；CI 结果也仅适用于其报告环境。没有新增真实来源兼容、完整正文搜索/交换、OS 冷缓存、NSIS 人工操作、干净 Windows 或生产升级验收。当前分页实现已达到本阶段指标，未引入额外缓存、索引迁移或时间线重构。
